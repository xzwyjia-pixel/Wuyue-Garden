# 飞书机器人 + AI 专家研讨集群 — 设计文档

日期: 2026-05-13
状态: 设计锁定

## 一、系统概述

搭建飞书群聊触发的 AI 多模型研讨系统。用户在飞书群@机器人 发送议题 → 系统调度多个 AI 模型并行分析 → 交叉辩论 → 深度推演 → 汇总结论 → 自动归档 Obsidian + 多格式导出。

## 二、技术栈

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | Python 3.10+ / FastAPI | 异步、生态成熟、代码简洁 |
| HTTP | aiohttp + httpx | 异步调用 AI API |
| 飞书 SDK | feishu (lark v2) | 官方 Python SDK |
| Excel | openpyxl | 无需 Excel 本地安装 |
| Obsidian | 直写文件系统 | vault 路径已知 E:/Obsidian/ |
| 部署 | uvicorn systemd (可选) | 生产级 |

## 五、研讨编排引擎

### 5.1 流程管线

```
Phase 1 — 并行分析
  输入：用户议题
  动作：所有启用的 AI 收到相同议题，独立分析
  输出：N 份独立分析报告（N = 启用模型数）

Phase 2 — 交叉辩论
  输入：Phase 1 全部报告
  动作：轮流向每 AI 展示其他 AI 观点，要求回应/反驳/补充
  循环：2-3 轮
  输出：辩论记录

Phase 3 — 深度推演
  输入：辩论记录
  动作：综合观点，推演不同路径结论，识别共识/分歧
  输出：共识列表 + 分歧列表

Phase 4 — 汇总结论
  输入：共识/分歧
  动作：生成结构化最终报告
  输出：核心结论 / 主要分歧 / 建议行动
```

### 5.2 策略模式

| 策略 | 流程 | 场景 |
|------|------|------|
| `parallel_only` | Phase 1 + Phase 4 | 快速多角度分析 |
| `full_debate` | Phase 1→2→3→4 | 完整研讨（默认） |
| `quick` | Phase 1 + 精简 Phase 4 | 追求速度 |

### 5.3 容错

- 单个 AI 超时/失败：跳过该模型，其余 AI 继续
- 至少 1 个 AI 成功即可输出结果
- 飞书消息发送失败：重试 2 次

## 六、飞书集成

### 6.1 事件订阅

- 接收 `im.message.receive_v1` 事件
- 验证 `@bot` 提及或群聊关键词
- 异步处理，先回复"收到，正在研讨..."占位消息

### 6.2 消息格式

- 文本消息 → 直接作为议题
- 图片/文件消息 → 暂不支持（设计预留）

### 6.3 多维表格（Bitable）

- 每次研讨自动记录到飞书多维表格
- 字段：时间 / 议题 / 参与AI / 结论摘要 / Obsidian链接

## 七、Obsidian 联动

### 7.1 笔记结构

```markdown
---
title: {议题标题}
date: {YYYY-MM-DD HH:mm}
tags: [AI研讨, {分类}]
participants: [Gemini, DeepSeek, Claude, ...]
strategy: full_debate
status: completed
---

# {议题标题}

## 并行分析摘要
...

## 辩论过程
...

## 共识
- ...

## 分歧
- ...

## 最终结论
...

## 导出文件
- [Excalidraw](excalidraw/{议题}.excalidraw.md)
- [Excel](exports/{议题}.xlsx)
```

### 7.2 Excalidraw 格式

生成标准 Excalidraw `.excalidraw.md` 文件，在 Obsidian 中可直接渲染为可视化思维导图。图形结构：

- 根节点：议题
- 一级分支：各 AI 观点
- 二级分支：共识 / 分歧

### 7.3 Excel 输出

- Sheet 1: 各 AI 逐条观点对比表
- Sheet 2: 共识/分歧清单
- Sheet 3: 时间线 + meta

## 八、自检系统

`src/main.py` 或 `start.py` 启动时执行自检：

| 检查项 | 通过条件 |
|--------|---------|
| 配置文件 | config.yaml 存在且格式正确 |
| 飞书凭证 | App ID / Secret 有效 |
| AI 模型 | 已配置 Key 的模型可达 |
| Obsidian 路径 | vault 路径存在 |
| 依赖 | requirements.txt 全部安装 |
| 端口 | 8000 端口未被占用 |

失败时打印清晰的错误信息和解决方案。

## 九、全局规则

- 所有 `Do you want to proceed?` 提示：自动选 `1.Yes`
- 所有非交互式确认：默认通过
- 超时重试：AI 调用超时 30s，重试 1 次
