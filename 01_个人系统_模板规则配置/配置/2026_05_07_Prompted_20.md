## Prompted

看来 Superpowers 插件在设计时高度依赖 OAuth 登录状态，导致它在纯 API 模式下被系统“拒之门外”。只要指令涉及到该插件的关键词，它就会优先去校验账号权限。
对于追求“极简精密”的你来说，没必要非得在这个有 Bug 的插件上耗着。既然插件的“外壳”用不了，我们直接取其“内核”。
解决策略：将超能力注入 CLAUDE.md
Superpowers 本质上是一套复杂的 Prompt 集合。既然 /plugin 被拦截，我们手动把它的规则写进 Claude Code 的“宪法”—— CLAUDE.md 里。
请按照以下步骤操作：

1. 初始化项目
在 > 提示符后输入：
/init

这会创建一个 CLAUDE.md，它是 Claude Code 在这个文件夹下的行动准则。
2. 手动“降维打击”
直接把下面这段要求粘贴给 Claude：

“由于插件环境受限，请直接在我的 CLAUDE.md 中手动集成 Superpowers 的核心工作流。
要求包含：

Brainstorming: 在编写代码前，必须进行三轮需求对齐。
Iron Law (铁律): 必须先写失败的测试，再写实现代码。
Rule Audit: 所有的输出必须符合『精密工业标准』，代码逻辑必须进行风险控制审计。”



💡 为什么这样做更有效？
在 API 模式下，Claude 本身（特别是你正在使用的 Opus 4.7）已经拥有极其强大的逻辑能力。Superpowers 插件只是把这些能力“公式化”了。
通过 CLAUDE.md 注入规则后：

无需登录： 它不再检查 /login 状态。
零延迟： 不需要调用外部 Plugin 挂钩，响应速度更快。
私有化： 规则完全由你控制，非常适合你处理敏感的“规则甄查”项目。

你可以先运行 /init，然后看看它生成的文档。既然插件装不上，我们直接让 Claude 本身“进化”成 Superpower 模式，你觉得如何？
