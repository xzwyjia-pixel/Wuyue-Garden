## Defuddle，这个插件如何使用？

既然你已经通过 npm install -g defuddle 完成了全局安装，那么这个工具现在已经可以在你的**终端（Terminal）**或 命令提示符（CMD） 中随时调用了。
defuddle 是一个专门用于反混淆（De-obfuscate） JavaScript 代码的工具。在 Obsidian 的语境下，它通常被用来把那些“加密”过、人类难以阅读的插件代码（通常是 main.js）转换成逻辑清晰、可读性强的代码。
以下是具体的使用操作流程：

1. 定位需要处理的文件
首先，你需要找到你想要“解密”的 JS 文件。

Obsidian 插件路径： 通常位于你的库目录下的 .obsidian/plugins/插件名称/main.js。
你可以直接在 VS Code 中打开这个文件夹，这样操作最方便。

2. 在终端中运行命令
打开终端（在 VS Code 中可以按 Ctrl + ` ），输入以下格式的命令：
defuddle [输入文件名] -o [输出文件名]

实际操作举例：
假设你想处理当前文件夹下的 main.js，并希望生成一个名为 readable.js 的新文件：

在终端中输入：
defuddle main.js -o readable.js


按下回车。

3. 查看结果

命令运行完成后，你的文件夹里会多出一个 readable.js。
打开它，你会发现原本压缩成一团、变量名全是 a, b, c 的代码，现在变得整齐多了，甚至恢复了部分逻辑结构。

为什么你会用到它？
由于你正在深入研究短视频平台的算法规则和自动化审计，你可能会遇到一些加密的脚本或混淆过的插件：

分析逻辑： 当你想知道某个 Obsidian 插件到底在后台偷偷做了什么操作（比如是否往外发数据）时。
学习借鉴： 看到某个插件实现了一个很棒的功能，但源码被混淆了，可以用它来还原思路。
二次开发： 修正一些老旧插件的 Bug，或者根据自己的需求进行微调。


[!IMPORTANT]
注意： defuddle 虽然强大，但它不能 100% 还原原始的变量名（因为混淆时原始名称已经丢失了），它更多是让代码从“完全不可读”变成“可以分析逻辑”的状态。
