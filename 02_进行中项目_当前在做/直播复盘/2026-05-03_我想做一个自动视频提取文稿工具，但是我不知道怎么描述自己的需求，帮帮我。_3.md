## 我想做一个自动视频提取文稿工具，但是我不知道怎么描述自己的需求，帮帮我。

从“想做个工具”到“写出需求文档”，中间差的是对工作流（Workflow）的拆解。既然是针对视频提取文稿，我们可以从输入、处理、输出、交互这四个关键环节来梳理。
你可以对照以下几个维度，看看哪些是你最想要的：
1. 输入端：你想让它“吃”什么？
描述需求时，首先要定义工具处理的对象：

本地文件： 直接上传 MP4、MOV 等视频。
在线链接： 粘贴视频号、抖音、B站或 YouTube 链接，工具自动解析并下载音频。
实时流： 针对直播间或会议视频流进行实时转写。
批量处理： 是一次处理一个，还是扔进去一个文件夹自动全部完成？

2. 核心处理：你希望它怎么“思考”？
这是决定工具“含金量”的部分，你可以这样描述需求：

识别精度： 是否需要支持中英混输？是否需要区分不同的发言人（角色分离）？
智能降噪： 如果视频背景音嘈杂（如工厂车间或户外），是否需要自动增强人声？
语义断句： 不仅仅是把字打出来，还能根据语调和语义自动加标点、分段落。
合规/过滤： 是否需要自动识别并标记视频中的敏感词或特定关键词？

3. 输出端：你想要什么样的“成品”？
提取出来的文稿最终长什么样：

纯文本 (TXT/Markdown)： 只要文字，追求极简。
带时间戳的字幕 (SRT/VTT)： 方便后期把文稿再导入视频编辑软件。
AI 摘要/脚本： 不只是原文，还要 AI 自动总结全文大意、提炼金句，甚至反向生成拍摄脚本。
翻译功能： 提取中文文稿的同时，自动生成英文或德文对照。

4. 交互与部署：你准备在哪里用它？

轻量化工具： 比如一个 Python 脚本，或者集成在 VS Code 里的插件（方便边看代码边看文档）。
本地化部署： 基于隐私和数据安全考虑，所有识别过程都在本地 GPU 运行，不上传云端。
自动化工作流： 比如“监控某个账号，一旦发新视频就自动提取文稿并推送到我的笔记软件”。


需求描述模版（你可以直接填空）：

“我想做一个**[ 本地运行 / 网页版 ]的视频文稿提取工具。
我希望它能直接识别[ 视频链接 / 本地视频文件 ]，核心要求是[ 识别速度快 / 区分发言人 / 自动翻译 ]。
输出的结果除了原文，还要包含[ 时间戳 / AI 摘要 / 关键点提炼 ]。
视觉上，我倾向于[ 极简精密 ]的风格。
主要是为了解决[ 整理视频素材效率低 / 需要分析大量短视频内容 ]**的问题。”

如果你目前有具体的硬件环境（比如已经配置好了 Python 环境或特定的显卡），或者有明确想针对的平台（比如专门针对视频号），可以告诉我，我帮你把需求写得更专业一些。
