## 同意，视频号

既然决定针对视频号进行“云监控”，我们可以利用视频号网页版（PC端）稳定的界面布局来实现自动化。通过 Claude Code，我们可以构建一个基于 Python + Playwright (或 Selenium) + OCR 的实时审计系统。
以下是为你量身定制的 Claude Code 指令集，你可以分步骤喂给它，逐步建立起这个监控系统。

第一步：环境与自动化爬虫搭建
这个步骤解决“如何拿到数据”的问题。视频号网页版在浏览器中可以清晰地定位到评论区 DOM 节点。

指令：
请在当前目录下编写一个 Python 脚本 wechat_live_monitor.py。

使用 Playwright 启动浏览器并打开指定的视频号直播间 URL。
定位逻辑： 识别视频号网页版直播间的“评论区”容器（通常是特定的 class 或 id），并实时抓取新出现的文本内容。
视觉采样： 每隔 60 秒截取一次直播画面区域（Canvas/Video 标签内容），保存到 tmp_frames/ 文件夹。
数据存储： 将抓取到的评论内容带上时间戳，实时追加写入到 live_chat_log.jsonl 中。



第二步：智能实时审计逻辑 (The "Cloud COO" Logic)
有了原始评论和画面，我们需要让系统能“看懂”正在发生什么。

指令：
请扩展 wechat_live_monitor.py 的功能，接入多模态分析逻辑：

关键词触发： 当 live_chat_log 中出现“多少钱”、“怎么买”、“荷花”、“海燕”等关键词密度激增时，在控制台高亮预警。
画面审计（利用 Vision 模型语义）： 每 5 分钟调用一次分析逻辑，判断画面中“实诚人、精致姐、海燕”三人的在场情况。
冲突检测： 重点监测评论区是否出现了对“主播互动、吵架、分南瓜”等内容的讨论，以此判定“人设冲突”是否生效。



第三步：下播后的自动化复盘报告 (The /triage & Improve)
这一步是给博主看的，解决“明天怎么改”的问题。

指令：
请编写一个复盘生成脚本 generate_post_stream_report.py。
逻辑如下：

加载数据： 读取本场直播的所有 live_chat_log.jsonl 和画面截图。
热度映射： 根据评论区的刷新频率，绘制一条“直播热度曲线图”。
AI 诊断 (/triage)： 对比“热度最高点”和“人均停留基线（1.14min）”，指出观众是在哪个环节被留住的（例如：是因为海燕的小脾气，还是因为实诚人的厨艺展示？）。
行动清单 (Improve)： 针对“北鼎级”高客单价定位，分析公屏对产品的提及率。如果提及率低，自动生成 3 条针对次日直播的“软植入冲突脚本”。



💡 你的操作流（如何运行）：

开播前： 在电脑上运行 npx @anthropic-ai/claude-code，然后执行 python wechat_live_monitor.py。
直播中： 你只需要偶尔看一眼 Claude Code 的控制台，它会通过 ASR/OCR 告诉你：“现在公屏都在讨论海燕，建议加强互动”。
下播后： 运行复盘脚本，生成一份 PDF 或 Markdown 报告发给主播。


📅 给博主的第一个“云端”反馈指令
由于你不在现场，你可以利用这套系统发现一个核心视觉指标：“视觉呼吸感”。

给 Claude 的指令：
“请分析截图，判断精致姐在背景中出现的频率和位置。如果她长时间挡住灶台，或者背景中的荷花被杂物遮挡，请在复盘报告中重点标注为‘视觉干扰’，并给出优化机位建议。”

这种方式的好处在于：你虽然不在现场，但你拥有比现场主播更理性的“上帝视角”。我们需要先从第一个“视频号公屏采集”的脚本代码开始写起吗？
