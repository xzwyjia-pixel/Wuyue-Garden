## 二、画面结构化分析 (视频采样证据)

### 2.1 三分区亮度分析

将画面纵向三等分, 测量各区域亮度:

| 区域 | 平均亮度 | 占比画面 | 内容 | 视觉效果 |
|------|---------|---------|------|---------|
| 左1/3 (0-427px) | **40.7** | 33% | 姐、树丛、暗角 | 几乎不可见 |
| 中1/3 (427-853px) | **74.4** | 33% | 苏苏、灶台 | 勉强可看 |
| 右1/3 (853-1280px) | **101.9** | 33% | 院子方向、光源 | 最亮区域 |

**结论:** 画面右端亮度是左端的2.5倍。左1/3画面(33%)实际是浪费的——观众看不到任何有价值的内容。

### 2.2 人脸检测分析 (OpenCV Haar Cascade)

| 指标 | 数值 |
|------|------|
| 人脸检测率(正对镜头) | **61%** |
| 无人脸时段(侧身/低头) | **39%** |
| 人脸平均亮度(检测到时) | 151.9/255 |
| 人脸平均占画面比 | 0.7% |

**解读:** 
- 39%的时间苏苏低头做菜/侧身对话, 观众看到的是后脑勺或侧脸
- 人脸被检测到时亮度151.9, 说明光源位置是够的——**问题不是光不够, 是苏苏没对准光**
- 人脸过小(0.7%画面)——手机端几乎看不清表情

### 2.3 厨房操作区专项分析

食物区域(画面中下70-95%高, 20-80%宽):

| 指标 | 全程均值 | 出锅展示时刻 |
|------|---------|-------------|
| 食物饱和度 | **19.7** | **59** (3倍提升) |
| 食物细节纹理 | 78.8 | 110+ |
| 食物区域亮度 | 65-72 | 75-85 |

> **关键结论:** 当苏苏把菜端到镜头前展示时, 食物饱和度从20飙到59。证明不是菜不好看, 是**常规机位太远, 菜的细节全丢了**。加一个近景手机立刻解决。

## 三、实时数据交叉验证

### 3.1 OCR真实有效性评估

| 指标 | 数值 |
|------|------|
| 总OCR扫描次数 | 175次 (每30秒) |
| 用户评论条数 | **0条** |
| 界面UI噪音比例 | 100% |
| 同噪词汇频率 | "嫩瞎" 98%, "士袄孑鸡拍" 95%, "发四!" 90% |

**解析:** 评论区OCR识别到的全是系统界面元素(时间戳、UI控件文字), 无一真实用户评论。说明:
1. 视频号当前直播间无公域推流或推流极少
2. 或评论区区域坐标不精确, 扫到的是界面UI而非评论区

## 四、改进建议 (基于交叉验证)

### 4.1 实时监控系统修正

| 问题           | 修正方案                                 |
| ------------ | ------------------------------------ |
| 评论区坐标不准确     | 下次开播前校准 --calibrate 模式               |
| 人脸检测未集成到实时监控 | 将OpenCV Haar Cascade加入triage_frame() |
| 区域亮度分析缺失     | 加入左/中/右三分区测量                         |
| 食物展示检测       | 当food_sat突然上升>50%时触发alert            |

### 4.2 直播质量提升 (新证据支撑)

**最高ROI改动 — 机位右移30cm**

证据: 左区域40.7 vs 右区域101.9 (2.5倍差距)

当前构图中, 33%是暗区(左), 33%是中等区(中), 33%是亮区(右)。苏苏站在中右位置。如果机位右移30cm:
- 左暗区缩小到15%
- 苏苏和灶台占据画面中心60%
- 右侧亮区占25%

画面有效利用率从约50% → 约85%。

**第二高ROI — 每8分钟面向镜头说话**

证据: 39%时间未检测到人脸

观众看烹饪直播想看的是**人**, 不是背影。苏苏做一个动作(如翻炒、放调料)后, 转头面向镜头说明3-5秒, 再继续操作。观众留存会明显提升。

**第三高ROI — 手机近景机位**

证据: 食物展示时刻饱和度翻3倍(20→59)

- 无需OBS: 旧手机+支架, 45°俯拍灶台
- 需要切换时, 把手机举到镜头前展示3-5秒
- 展示时机: 食材下锅、出锅装盘、成品展示
