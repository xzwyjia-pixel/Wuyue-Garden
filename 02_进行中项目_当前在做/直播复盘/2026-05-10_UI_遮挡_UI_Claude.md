## UI 遮挡

针对你“一机双播”的特殊场景，UI 遮挡是运营中最容易被忽视的“转化杀手”。
抖音的评论区在左下方，且有各种挂载组件（如小黄车、品牌标签）；而视频号的评论区相对较矮，但右侧有密集的点赞动画和“福袋”等挂件。如果苏苏展示产品的动作没有经过精准计算，就会出现**“抖音看得到，视频号被挡住”**的尴尬局面。
以下是针对“UI 遮挡”的系统级优化方案，请将其交给 Claude 执行。

1. 建立“双平台安全区”视觉模板
我们需要在监控引擎中加入一层“虚拟 UI 遮罩”。
请将以下指令发送给 Claude Code：

请执行 UI 遮挡风险监测逻辑：


定义安全热区 (Safe_Zones)： >    - 在 monitor_engine.py 中引入两组遮罩坐标：

DY_Mask: 底部 30% 区域（评论区）及右侧 20%（头像/点赞）。
WCH_Mask: 右下方 40% 区域（点赞动画/礼物弹窗）。
核心安全区 Ultimate_Safe_Zone 应为两者的交集空隙（通常是画面中心偏上 15% 的位置）。



执行视觉检测： >    - 当 product_detail > 80（识别到主播在展示产品）时，检测 Center_of_Mass（物体视觉重心）是否落入上述 Mask 区域。


实时报警： >    - 若产品被遮挡，在控制台打印红色预警：!!! [UI 遮挡预警] 产品正被抖音评论区或视频号组件覆盖，请提醒主播上移手部 !!!


辅助校准： >    - 运行一次 generate_ui_overlay.py，生成一张带有两端 UI 遮罩的透明参考图，存入 Audit_Assets/Calibration/ 供运营人员对比。




2. 运营层面的物理改进（基于 AI 反馈）
一旦系统开始跑起来，你会发现一些规律。基于此，我给“苏苏在浙里”和“清晨烟火小厨”后台运营的建议如下：


“黄金中心点”定位： 通过监控你会发现，最安全的位置其实是苏苏胸口正前方、靠近下巴的位置。

动作建议： 在灶台或桌面上贴一个“视觉锚点”（例如一张只有你能看到的彩色胶带）。告诉主播，每次拿罐子展示，必须对准这个锚点。



“异构 UI”适配：

视频号侧： 注意右下角的“爱心”连发。如果苏苏在右侧切菜，画面会被爱心挡死。
抖音侧： 注意左下角的“系统推流提示”。如果产品拿得太低，会被抖音的“XXX进入直播间”完全遮住产品名称。




3. 反向完善：UI 穿透审计逻辑
为了让监控系统更聪明，我们要让它具备“感知遮挡”的能力：

文本完整性校验： 如果系统在安全区外识别到“山胡椒”三个字，但只读出了“山...”，说明被挡住了。
对比度突变监测： UI 组件（如点赞按钮）通常是高亮色。如果原本应该显示食物的区域突然出现了高频率的“白色/红色”色块跳动，系统应自动判定为 UI_Interference（UI 干扰） 并在报告中扣除视觉分。


💡 运营行动清单：

让 Claude 跑脚本： 先把 UI 遮挡的报警逻辑写进 monitor_engine.py。
实测： 让苏苏在直播间故意把产品拿低、拿偏，看控制台是否跳出 [UI 遮挡预警]。
微调： 根据报警频率，调整物理锚点，直到系统不再报错。

通过这一步，你就能确保：不管是抖音还是视频号的观众，看到的都是最完整、最诱人的产品细节。
