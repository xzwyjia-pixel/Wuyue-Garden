## Prompted

甄先生，咱们现在已经完成了“双机备份”的最后一步。针对您如何确认 GPTs API 的 Key 是否正确，以及如何进行测试，以下是为您定制的精密检查方案：
一、 确认 Ollama 状态（image_ec4037.png）
您在终端看到 >>> 符号，说明 Qwen2.5-Coder 已经在本地后台就绪。这个窗口现在可以关闭了，它不会影响 CodeAI 调用本地算力。
二、 如何精准确认并测试云端 API Key
要确认您在 VS Code 里输入的 Key 是否就是刚充值了 $10 的那个，最稳妥的方法不是靠记忆，而是靠“后台对比法”：


第一步：去后台重新“拿”一次 Key

登录您的 GPTs API 控制台（即显示 $10 余额的界面）。
点击左侧菜单的 “API Keys”。
如果您不确定之前用的是哪个，建议直接点击 “+ 创建密钥”，现场生成一个全新的 Key 并点击复制。



第二步：在 VS Code 中精准替换

打开 CodeAI 的设置界面（点击齿轮图标）。
将 API 供应商 选为 Anthropic。
清空 Anthropic API Key 输入框，粘贴您刚才从后台新复制的 Key。
关键点：确保勾选了 Use custom base URL，且下方地址填的是 https://api.gptsapi.net。
点击右上角的 “确定” 保存。



第三步：实战命令测试
您不需要敲代码，直接在聊天框发送下面这段话给 AI：

“甄查官测试：请列出当前工作区的所有文件名，并告诉我你现在使用的具体模型名称。”



三、 结果判定标准

测试成功：AI 会立刻列出您的文件，并回复类似“我正在使用 Claude-3-5-Sonnet”。此时您回到 GPTs API 后台刷新，会发现余额从 $10.00 变成了 $9.99 左右。只要余额动了，就证明 Key 100% 正确且通电了。
测试失败（报错 401）：说明 Key 粘贴得不对。
测试失败（报错 404）：说明 https://api.gptsapi.net 这个地址填错了。

甄先生，建议您现在就去后台新建一个 Key 重新粘贴一次，这样最保险。只要这口气接通了，咱们的审计引擎就正式进入“满血状态”！
