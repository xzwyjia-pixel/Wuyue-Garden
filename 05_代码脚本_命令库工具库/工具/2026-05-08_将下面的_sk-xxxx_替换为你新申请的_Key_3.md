## 我删除了原来已经暴露的 ＡＰＩｋｅｙ．现在我申请了新的。该如何更新在ｐｏｗｅｒｓｈｅｌｌ（）

既然你已经申请了新的 API Key，为了确保你的“规则甄查”项目和终端环境能够长期、稳定地使用这个新密钥，建议你按照以下三个维度进行更新。
这种方式可以避免以后每次打开 PowerShell 都要重新输入。
1. 永久更新系统环境变量（推荐）
直接在 PowerShell 中运行以下命令，这会将新 Key 写入 Windows 用户变量中。以后开机或打开新窗口都会自动生效。
# 将下面的 sk-xxxx 替换为你新申请的 Key
$newKey = "sk-你的新API密钥"

# 永久写入用户环境变量
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", $newKey, "User")
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", $newKey, "User")
[Environment]::SetEnvironmentVariable("OPENAI_BASE_URL", "https://api.deepseek.com/v1", "User")

Write-Host "✅ 永久环境变量已更新！请重启 PowerShell 窗口以生效。" -ForegroundColor Green


2. 更新当前窗口（立即生效）
如果你不想重启窗口，想立刻开始调试审计脚本，请运行：
$env:DEEPSEEK_API_KEY = "sk-你的新API密钥"
$env:OPENAI_API_KEY = "sk-你的新API密钥"


3. 一键验证新 Key 是否有效
更新完后，建议运行这个“加固版”验证脚本。它采用了我们之前测试成功的 curl.exe 数组模式，能够完美处理 2026 版 DeepSeek 的 SSL 重协商问题。
$testKey = $env:DEEPSEEK_API_KEY
Write-Host "📡 正在验证新密钥连通性..." -ForegroundColor Yellow

$curlArgs = @(
    "-k", "-s", "-o", "/dev/null", 
    "-w", "%{http_code}", 
    "-X", "POST", "https://api.deepseek.com/chat/completions",
    "-H", "Authorization: Bearer $testKey",
    "-H", "Content-Type: application/json",
    "-d", '{"model":"deepseek-chat","messages":[{"role":"user","content":"hi"}]}',
    "-x", "http://127.0.0.1:7890"
)

$code = & curl.exe @curlArgs

if ($code -eq "200") {
    Write-Host "🚀 验证成功！状态码 200，新 Key 已完全就绪。" -ForegroundColor Green
} else {
    Write-Host "❌ 验证失败。状态码: $code。请检查代理是否开启及 Key 是否正确。" -ForegroundColor Red
}


💡 特别提醒：VS Code 审计工具同步
如果你在 VS Code 中使用 Cloud Code 或运行 audit_tool.py，请检查一下你的 .env 文件或插件设置：

如果你的 Python 脚本用了 os.getenv('DEEPSEEK_API_KEY')：那么执行完上面的“永久更新”并重启 VS Code 后，脚本会自动识别新 Key。
如果是插件设置：记得点击左下角齿轮 -> 设置 -> 搜索 DeepSeek，手动把旧的 sk-xxxx 删掉换成新的。

这次更新后，你的“规则甄查”链路就彻底安全且稳固了。如果运行审计命令时还有其他报错，随时贴给我看。
