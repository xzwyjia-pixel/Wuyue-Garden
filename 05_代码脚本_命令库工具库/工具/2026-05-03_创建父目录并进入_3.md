## requests.exceptions.HTTPError: <Response [404]>
(venv) PS E:\> cd E:\git_project\GPT-SoVITS
Set-Location: Cannot find path 'E:\git_project\GPT-SoVITS' because it does not exist.
(venv) PS E:\>

看来我们在路径上玩了一场“躲猫猫”。 报错显示 E:\git_project\GPT-SoVITS 不存在，这说明虽然你之前尝试过 git clone，但可能因为报错或中断，文件夹并没有成功建立在 E 盘，或者它的名字不叫这个。
别担心，我们用最稳妥的**“路径重建法”**，直接在当前位置把项目拉下来：
1. 重新克隆项目（确保路径正确）
既然你在 E:\ 根目录，且已经激活了 (venv)，请直接执行：
# 创建父目录并进入
mkdir -p git_project
cd git_project

# 重新克隆项目（这次我们盯着它跑完）
git clone https://github.com/RVC-Boss/GPT-SoVITS.git

2. 进入新下载的目录
cd GPT-SoVITS

3. 再次尝试下载模型
现在你已经脚踏实地踩在项目目录里了，再次运行下载指令：
python -c "from modelscope import snapshot_download; snapshot_download('iic/GPT-SoVITS', local_dir='GPT_SoVITS/pretrained_models')"


🔍 为什么会发生这种情况？

克隆失败：之前的 git clone 可能因为网络波动没写进磁盘，导致 cd 找不到门。
盘符混淆：你最早提到的目录是在 D 盘 (D:\git_project\GPT-SoVITS)，如果你之前是在 D 盘做的操作，那么在 E 盘自然找不到它。

💡 极简排查小贴士：
如果你不确定文件夹到底在哪，可以输入 ls (或者 dir) 看看当前目录下有没有 git_project 这个文件夹。
请先尝试 mkdir 和 git clone。如果 git clone 提示 destination path 'GPT-SoVITS' already exists，说明文件夹其实在，只是名字里可能有空格或大小写不同，到时候告诉我，我教你用 Tab 键自动补全路径。
