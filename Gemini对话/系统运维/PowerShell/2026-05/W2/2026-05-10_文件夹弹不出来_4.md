## 文件夹弹不出来

如果 file:/// 协议在 Obsidian 里都无法弹出文件夹，说明问题已经不在代码语法上，而是 Obsidian 的 API 写入权限或 Windows 对本地文件链接的策略拦截。
由于你使用的是 Local REST API 插件，我们直接用“以毒攻毒”的办法，让插件自己通过它的配置逻辑来修复这个连接。
请按照以下三个步骤操作，这能绕过所有复杂的协议跳转，直接打通：
1. 检查 Obsidian 插件的“白名单”
Obsidian 出于安全考虑，有时会拦截未经授权的本地路径请求。

进入 Obsidian 设置 -> Community Plugins。
找到 Local REST API 插件，点击右侧的设置图标。
确认插件是否处于 Active 状态。
向下滚动，看看有没有 Allowed Origins 之类的设置，通常保持默认或 * 即可。


2. 终极“暴力”修复脚本
有些时候，Obsidian 对 vscode:// 和 file:/// 的解析需要非常严格的编码。我为你写了一个**“纯路径版”**，去掉了所有可能引起歧义的符号，并强制使用 Windows 认可的绝对路径格式。
请再次运行此 PowerShell 代码：
$apiKey = "8212fe30470f760008c2bc5a9faa24f07d838267fc995c09b8292a8464ab770c"
$sourceDir = "E:\Mycodeprojects"
$apiVaultUrl = "http://127.0.0.1:27123/vault/Michael_Product"

$projects = Get-ChildItem $sourceDir -Directory | Where-Object { $_.Name -notlike ".*" -and $_.Name -notlike "__*" }
$headers = @{ "Authorization" = "Bearer $apiKey"; "Content-Type" = "text/markdown" }

foreach ($project in $projects) {
    $name = $project.Name
    $path = $project.FullName
    
    # 强制构建符合 Windows 规范的文件链接
    # 注意：file:/// 后面必须跟磁盘号
    $fileLink = "file:///" + $path.Replace("\", "/")
    $vsLink = "vscode://file/" + $path.Replace("\", "/")

    $content = @"
# Project: $name

## Path
$path

## Commands
- [🚀 Open in VS Code]($vsLink)
- [📂 Open in Explorer]($fileLink)

---
- [[Michael_Product_MOC]]
"@

    $targetUrl = "$apiVaultUrl/$name.md"
    Invoke-RestMethod -Method Put -Uri $targetUrl -Headers $headers -Body ([System.Text.Encoding]::UTF8.GetBytes($content))
}
Write-Host "✅ 链接重构完成。请重启 Obsidian 后尝试。" -ForegroundColor Cyan


3. 如果点击依然没有反应（最关键的一步）
如果运行完上面的脚本，点击链接依然没反应，请尝试这个**“手动降级方案”**来定位问题：

手动输入测试：在 Obsidian 任意一个笔记里，手动输入：
[测试打开E盘](file:///E:/Mycodeprojects)
切换到“阅读模式”（快捷键 Ctrl + E）。
点击它。

如果弹出来了：说明我之前脚本生成的 Markdown 格式被你的某个插件篡改了。
如果还是弹不出来：说明你的 Windows 注册表里 file 协议的关联坏了，或者 Obsidian 的 安全沙箱 权限被你的防火墙/杀毒软件限制了。



🛠️ 针对 VS Code 打不开的补充：
如果文件夹能打开，但 VS Code 打不开，请尝试在 VS Code 里：

按下 F1。
输入 Shell Command: Install 'code' command in PATH 并执行。
重启电脑。这会强制重置 VS Code 的所有协议关联。

请先试一下手动输入那个 [测试打开E盘] 链接，看看 Obsidian 本身还有没有权限访问你的硬盘？
