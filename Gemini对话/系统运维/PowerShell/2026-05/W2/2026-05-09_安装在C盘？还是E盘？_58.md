## 安装在C盘？还是E盘？

根据你 ThinkPad P15V 的配置（作为专业技术生产力工具）以及你正在开发的 AI 语义文件夹图标可视化等项目的需求，建议如下：
1. 结论：安装在 C 盘（默认路径）
所有的 Node.js 全局工具（npm install -g）都应该保持在 C 盘默认路径。
虽然你有 E 盘作为存储空间，但对于 Everything Claude Code、GSD、OpenSpec 这些工具，安装在 C 盘有以下三个决定性优势：

路径依赖与兼容性： 绝大多数 AI 编程工具和 MCP (Model Context Protocol) 协议默认会在 %AppData% 或 C:\Users\用户名\.npm-global 下寻找配置文件。安装在 E 盘可能会导致 Claude Code 找不到这些扩展。
读取性能： 你的 P15V 系统的 C 盘通常是高速 NVMe SSD。这些工具在运行（尤其是 GSD 处理大量代码上下文时）需要频繁读取小文件，放在 C 盘响应最快。
环境变量简单： 放在 C 盘，Windows 的环境变量（Path）会自动处理。跨盘符调用工具链（从 C 盘的 Claude 运行 E 盘的脚本）有时会触发 PowerShell 的权限安全拦截。


2. 什么是该放 E 盘的？
虽然 工具（Tools） 装在 C 盘，但你的 代码仓库（Repos） 和 AI 模型（Models） 应该放 E 盘：

项目代码： 你的“Rule Investigation”品牌代码、AI 代理项目等。
本地 LLM 模型： 如果你后续通过 Ollama 或 Docker 运行 DeepSeek、Qwen 等模型，这些动辄几十 GB 的文件必须放 E 盘。
缓存： 比如 Python 的虚拟环境（venv）或大型 Node 模块（node_modules），它们才是占用空间的元凶。


3. 操作建议
既然你准备在 PowerShell 里运行安装命令，直接执行即可，不需要手动切换盘符。npm 会自动把它们塞进 C 盘的全局目录中。
执行安装后的检查技巧：
安装完后，如果在 PowerShell 输入 gsd 报错，运行这个命令查看你的工具到底装哪了：
npm config get prefix

通常它会显示 C:\Users\你的用户名\AppData\Roaming\npm，这就是它们最该在的地方。

一句话总结：
让**“锄头”（工具）留在 C 盘系统库里，把“地”**（项目代码）种在 E 盘。
