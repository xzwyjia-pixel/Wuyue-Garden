## 表达式或语句中出现意外的标记66-cad"

这个错误（Unexpected token '66-cad'）通常发生在 PowerShell、JavaScript 或类似的编程环境中。
根本原因在于：你输入的字符串或变量名中包含了连字符（-），但没有用引号将其括起来。 在代码解析器看来，- 是一个减法运算符，它尝试计算 66 减去 cad，结果发现语法完全对不上。
针对你目前正在调试的 DeepSeek API Key 和 PowerShell 环境变量 场景，这里是修复方案：
1. 最常见的原因：API Key 缺少引号
如果你在设置变量时，直接粘贴了 Key 而没打引号，PowerShell 会报错：

错误写法： $env:DEEPSEEK_API_KEY = sk-66-cad...
正确写法： $env:DEEPSEEK_API_KEY = "sk-66-cad..."


2. 解决方法：重新注入（带引号版）
请在 PowerShell 中直接运行下面这段加固过的命令：
# 务必确保 Key 被双引号括起来
$myNewKey = "sk-66-cad-请替换为你完整的Key" 

# 更新当前窗口变量
$env:DEEPSEEK_API_KEY = $myNewKey
$env:OPENAI_API_KEY = $myNewKey

# 再次永久写入系统（确保万无一失）
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", $myNewKey, "User")

Write-Host "✅ 修正成功！'66-cad' 已被识别为字符串的一部分。" -ForegroundColor Green


3. 深度排查：脚本路径名
如果你是在运行脚本时报错，检查你的文件夹名称或脚本文件名是否叫 66-cad。

如果文件夹叫 66-cad-audit，你在跳转目录时必须这样写：
cd "C:\YourPath\66-cad-audit" （必须带引号）

💡 提示
这个报错说明你的 PowerShell 已经开始解析你输入的内容了，只是卡在了格式上。只要把那串包含 66-cad 的内容用 " (双引号) 包裹起来，问题就能立刻解决。
你可以试着再次运行命令，如果还有报错，请把报错前后的那一整行代码贴出来。
