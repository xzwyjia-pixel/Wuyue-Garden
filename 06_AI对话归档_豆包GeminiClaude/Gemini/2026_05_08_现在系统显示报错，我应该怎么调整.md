## 现在系统显示报错，我应该怎么调整？

甄先生，从您最后一张截图（图 36）来看，Cline 左侧面板弹出的 [OPENAI] 401 "Balance is insufficient" 报错已经给出了最终答案：中转站的余额不足。
虽然您之前给 DeepSeek 官方充值了 100 元，但因为您在 Cline 中使用的是第三方中转地址 api.gptsapi.net，这两者是完全独立的账户系统。
为了让您的“规则甄查”工作站立即恢复运转，我建议按以下逻辑进行精准调整：
1. 核心矛盾：官方余额 vs. 中转站余额

现状：您的 100 元充值在 DeepSeek 官方（图 31），但 Cline 目前请求的是 GPTSAPI 中转站。中转站由于检测不到它自己系统内的余额，所以返回了 401。
解决对策：将 Cline 的配置从“中转站模式”切换为“官方直连模式”。


2. Cline 配置调整步骤（直连 DeepSeek 官方）
请在图 35/36 的设置界面中修改以下三个关键参数：

使用自定义 URL (Base URL):

修改前：https://api.gptsapi.net
修改后：https://api.deepseek.com (这是官方直连地址，能直接用上您那 100 元)。


API Key:

修改前：中转站的 Key。
修改后：填入图 32 中您刚创建的官方 Key：sk-c8cf2fa5efc44b29b84f4ef6a7b9706e。


Model (模型):

手动输入：deepseek-chat。




3. 环境审计：为什么 Claude Code 能连但 Cline 报错？

Claude Code (图 33)：您之前在命令行里已经改用了 api.deepseek.com，所以它能识别您的 100 元余额并显示 API Usage Billing。
Cline (图 36)：它还“固执”地拉着旧的中转站链接，所以报了欠费。
