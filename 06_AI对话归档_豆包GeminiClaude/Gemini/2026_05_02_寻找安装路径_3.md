## Prompted

看到 image_062f50.png，你已经完成了第一步安装。不过由于 hermes-engine 是一个主要面向 React Native 项目的库，它安装后并不会直接把可执行文件放到全局路径里。
1. 为什么直接输入 hermes 没用？
这个 npm 包虽然成功下载了，但它是作为“依赖库”存在的。你看到的警告（deprecated）是因为现在 Hermes 通常直接集成在 React Native 0.70+ 版本中，不再鼓励单独安装旧版的 npm 包。
2. 找到你的“甄查”工具
如果你想在 WSL 里直接使用 Hermes 的命令行工具（比如 hermesvm 或 hermesc），最快的办法是直接在 node_modules 里翻出它的“真身”：
# 寻找安装路径
find /usr/lib/node_modules/hermes-engine -name "hermes*"

通常二进制文件位于：
/usr/lib/node_modules/hermes-engine/linux64-bin/hermesc（编译器）
/usr/lib/node_modules/hermes-engine/linux64-bin/hermes（虚拟机）
3. 配置全局命令（推荐）
为了像在 image_108995.png 里操作 npm 一样顺手，你可以给它建立软链接：
# 建立软链接到全局路径 (路径可能因版本略有不同，请根据上一条 find 命令结果调整)
sudo ln -s /usr/lib/node_modules/hermes-engine/linux64-bin/hermesc /usr/local/bin/hermesc
sudo ln -s /usr/lib/node_modules/hermes-engine/linux64-bin/hermes /usr/local/bin/hermes


⚠️ 一个重要的“规则甄查”提醒：
你在 image_062f50.png 的终端顶部看到的那行：

wsl: 检测到 localhost 代理配置，但未镜像到 WSL...

这说明你的 WSL 网络环境和 Windows 宿主机的代理（比如梯子）还没完全打通。这会导致你在 WSL 里使用 npm 或者未来使用 hermes 抓取远程规则时出现网络超时。
建议解决方式：
在 WSL 中执行以下命令，让它引用 Windows 的代理端口（假设你的代理端口是 7890）：
export http_proxy="http://127.0.0.1:7890"
export https_proxy="http://127.0.0.1:7890"
