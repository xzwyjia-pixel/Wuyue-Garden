## Prompted

从截图看，VS Code 配置文件已经成功强制更新了（绿色打钩），但测试环节依然卡在 unexpected EOF。这说明你的代理软件在处理 PowerShell 的 API 请求时，握手还是被切断了。
既然配置文件已经改好，其实你现在重启 VS Code 就可以直接用了。但为了追求“全自动化”和“验证通过”，我为你提供一个终极兼容版。
这个版本改用了 curl.exe（因为它比 PowerShell 原生的 Invoke-RestMethod 对代理中转站的兼容性强得多），并针对中转站常见的 /v1 路径问题做了自动修复。
终极一键粘贴脚本（使用 curl 验证）
# 1. 填入你的参数
$myBaseURL = "https://你的中转域名.com/v1"
$apiKey = "你的_API_KEY"

# 2. 直接执行（配置文件已改，此脚本侧重于链路验证）
Write-Host "📡 正在使用 curl 引擎进行深度验证..." -ForegroundColor Yellow

# 格式化 URL，确保不会因为多一个或少一个 /v1 报错
$cleanURL = $myBaseURL.TrimEnd('/')
if ($cleanURL -notlike "*/v1") { $testURL = "$cleanURL/v1/messages" }
else { $testURL = "$cleanURL/messages" }

# 使用 curl.exe 绕过 .NET 的 EOF 限制
# -k 忽略证书，-x 强制走代理（如果你的代理不是7890请修改下行）
$curlCmd = "curl.exe -k -s -X POST `"$testURL`" " + `
           "-H `"x-api-key: $apiKey`" " + `
           "-H `"anthropic-version: 2023-06-01`" " + `
           "-H `"Content-Type: application/json`" " + `
           "-d `"{`"model`": `"claude-3-5-sonnet-20240620`", `"max_tokens`": 10, `"messages`": [{`"role`": `"user`", `"content`": `"hi`"}]}`" " + `
           "-x http://127.0.0.1:7890"

$result = iex $curlCmd

if ($result -like "*content*") {
    Write-Host "🚀 验证成功！中转站响应正常。" -ForegroundColor Green
    Write-Host "现在你可以直接打开 VS Code 使用 Cloud Code / DC 插件了，配置已生效。" -ForegroundColor Cyan
} else {
    Write-Host "❌ 依然失败。返回结果如下：" -ForegroundColor Red
    $result | Write-Host
    Write-Host "`n💡 排除建议：`n1. 检查中转站后台，确认 API Key 是否有余额。`n2. 在代理软件（如Clash）日志里看是否有 403 或 Connection Reset。" -ForegroundColor Yellow
}

为什么这个版本大概率能过？

绕过 .NET 限制：之前的 unexpected EOF 是 PowerShell 底层 .NET 库的锅。curl.exe 是独立的原生程序，对这种中转 TLS 握手的容错率极高。
强制代理注入：脚本通过 -x http://127.0.0.1:7890 强行让流量走你的代理端口，不依赖系统全局变量。
路径自动修正：它会自动判断你的 URL 是否需要补全 /v1/messages。

你现在只需：

运行这段脚本看是否变绿。
直接去用你的 Cloud Code 审计工具。因为你的 settings.json 已经在上一步变绿时改好了，DC 模型现在应该已经可以调通了。
